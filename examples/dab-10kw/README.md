**AI-GENERATED ENGINEERING PROTOTYPE - HUMAN REVIEW REQUIRED - NOT HARDWARE QUALIFIED.** Three native KiCad 10
projects generated by `automation/dab_v1` from the requirement files in `requirements/`. Clean ERC/DRC results are CAD
statements about the generated files under the recorded rule set; they establish neither electrical safety nor
manufacturability. No fabrication, procurement or energisation is authorised by anything in this directory.

## Reproduction

Host Python 3.10+ (PyYAML optional) and KiCad 10 (kicad-cli and its bundled Python, found by `automation.setup.detect_kicad`).

```text
python -m automation.dab_v1.schematics --board primary-power --erc       # libraries, hierarchical schematic, rules, ERC
<KiCad python> -m automation.dab_v1.floorplan --board primary-power      # placement and copper plan (pcbnew)
python -m automation.dab_v1.copper --board primary-power                 # merge the pour rectangles (Shapely)
<KiCad python> -m automation.dab_v1.routing --board primary-power        # grid_router.run_plan through PairwiseRouter
python -m automation.dab_v1.verify --board primary-power                 # DRC, exports, netlist equality, quality, layout, islands
python -m automation.dab_v1.pipeline --board primary-power               # the four stages in sequence
python -m automation.dab_v1.provenance                                   # re-fetch and hash the manufacturer sources
python -m pytest tests/test_dab_v1.py -q
```

Repeat with `secondary-power` and `control`. Regeneration reproduces the schematic bytes and the placement; routed
copper is reproduced item for item but not byte for byte (random KiCad item ids), so compare geometry and the hashed
manifests, not file bytes.

## What is in the requirement files

- `specification.yaml` - user requirements, engineering assumptions, derived operating point, unverified design
  targets, verification policy.
- `design_constraints.yaml` - stack-ups, minimum features, the IEC 60664-1 reference table (clearance by impulse,
  creepage PD2 MG I, interpolated functional spacing, 8.0 mm reinforced HV-to-SELV), the potential model of the HV
  domains and the router defaults.
- `components.yaml` - every part selection with manufacturer source and the verification level of its pin table or
  envelope.
- `interfaces.yaml` - the 40-way harness map (identical on all three boards), the assumed controlCARD contact map,
  JTAG, CAN, RS-485, auxiliary input, heat-sink NTC and HV terminals.
- `floorplan_<board>.yaml`, `routing_<board>.yaml` - placement geometry and router parameters.
