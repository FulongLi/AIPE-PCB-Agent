# AIPE-PCB-Agent V2.1 — Schematic & Routing Quality Upgrade

## Summary

V2.1 upgrades the presentation of the V2 400 V (360-440 V) to 200 V, 5 kW SiC synchronous buck
(`examples/sic-buck-400v-200v-5kw/`, EX below) without changing its electrical design. The two
KiCad schematics are redrawn as wired engineering schematics in functional groups (pin-stub
global labels 648 -> 7 on the power board and 667 -> 7 on the control board, wired pin share
0 -> 0.897 and 0 -> 0.757), and both boards are re-routed with the upgraded grid router, which now
simplifies its own copper and ends runs in 45-degree chamfers and tangent `PCB_ARC` fillets
(90-degree bends 3609 -> 1121 and 4069 -> 1233, routed length -3.5 % and -5.0 %, same via count,
no net longer). Topology, components, operating specification, net classes, design rules and
placement are the V2 ones; the netlist is identical to the frozen V2 release by construction and by
gate; native ERC and DRC are at zero findings with schematic parity and all severities. The
improvements are reusable modules of the automation (router style key, path geometry, routing
quality checker, schematic presentation layer, readability metrics, release freeze), not manual
edits of this example. Every number below names its source file in EX; the frozen V2 release
`releases/v2/` is the "before" state and is untouched.

## What changed

- **Router** (`automation/kicad_tools/grid_router.py`): one new plan key `style` (defaults in
  `STYLE_DEFAULTS`, validated by `normalise_style`; a plan without it runs the unchanged V2 search - attempt C
  reproduced the frozen V2 quality totals, 4755 tracks, 606 vias, 5744.6 mm, 3609 bends_90, while board bytes
  still differ through random KIIDs; `routing_iterations_power.md` 16.3).
  `style.diagonal` switches `Grid.astar` to 8 directions with an octile heuristic, a no-corner-cutting
  rule and parent-direction bend penalties in cells; `style.simplify = 'octilinear'` and `style.arcs`
  run the new final stage `Router.beautify` after via pruning and before the ground pours: per chain of
  router-made tracks between pads, vias and junctions, octilinear string pulling, short-run collapse
  and on-grid 45-degree chamfers validated by the exact grid rule of the search, then tangent fillets
  with adaptive radius validated by a corridor test on the dilated foreign mask. A chain is rewritten
  whole or kept whole, so no net gets longer, no via moves and no width changes; `smooth_policy` keeps
  arcs off power, critical and wide nets unless the plan says otherwise. Shared pure-Python geometry in
  the new `automation/kicad_tools/path_geometry.py`.
- **Checker** (`automation/verification/check_routing_quality.py`, new): segments, arcs, vias,
  length, 90 / 45 / other bends, direction changes, stair and zigzag runs, short segments, routing
  efficiency, arc continuity, per board / layer / net / attribution (router, pre-routed, pad link),
  remaining 90-degree bends by reason, compare mode (before / after with per-net regressions), DRC
  manifest linkage. Uses the same chain extraction as the router.
- **Schematic generator**: `project_schematic.ProjectSpec.presentation` selects the drawing. `None` /
  `legacy` draws the V2 one-global-label-per-pin style from the same model (code path unchanged; the sheets
  differ from the V2 release in the generation label - rev `V2.1`, banner - and no byte comparison was
  recorded); a `wired` presentation dict goes through the new
  `schematic_presentation` planner (net roles rail / cross / local, functional groups from
  `Circuit.block()` or automatic grouping, signal-flow lanes, decoupling rows, one sheet per page with
  paper escalation A3 -> A2, root sheet as a port wall), `schematic_wiring` (orthogonal sheet router,
  KiCad connection normalisation, connectivity guard that re-derives `(ref, pad) -> net` from the drawn
  geometry before any file is written) and the extended `native_schematic` emitter (rotations,
  junctions, hierarchical labels, power symbols, DNP). `schematic_metrics` measures V2 and V2.1 sheets
  with one definition. `generate_sic_schematics` gained `--style wired|legacy`, `--gates` (six
  acceptance gates) and `--readability` (V2 vs V2.1 report).
- **Board generators**: `generate_sic_power_board.py --style default|octilinear|v21|none`
  (`ROUTING_STYLE = ROUTING_STYLE_OCTILINEAR`), `generate_sic_control_board.py` default `ROUTING_STYLE`
  with `--no-style` for the V2 geometry; both record `style`, `arcs`, `beautify` and `routing_quality`
  in `verification/routing_progress_<board>.json` and set the footprint DNP attribute from the model
  for schematic parity. The control generator also became deterministic in its stage-2 zones
  (corridor order, zone KIIDs; commit `7f93a61`).
- **Label**: one generation label `sic_buck_common.GENERATION = "V2.1"` feeds every title block,
  silkscreen, JSON record, PDF and `.kicad_dru` header (`verification/v21_validation.md` item L).
- **Freeze**: `automation/scripts/freeze_release.py --version v2.1` (generalised `freeze_v2`): runs the
  verifier first, never overwrites, writes `releases/v2.1/` with `SHA256SUMS.json` and the portable

## General vs board-specific improvements

General (reusable by any board or project built with the automation): the `style` plan key and
every stage behind it (8-direction search with bend penalties, octilinear simplification, short-run
collapse, chamfers, adaptive tangent fillets, smoothing policy, overlap-anchor rule), `path_geometry`,
the routing quality checker, the `presentation` layer of `project_schematic` (planner, sheet router,
connectivity guard, emitter), `schematic_metrics`, `Circuit.block()`, the generation label and
`freeze_release`. Board-specific in this round: the choice of style block per board (`straight_nets=['PE']`
and eps 0.01 on the power board, eps 0.02 on the control board), the `Circuit.block()` annotations and
the `PRESENTATION` rail policy (`exclude_supply=['5V_SW']`) in the SiC models, the DNP attribute, the
scratch-build `--outputs` mode of the power generator, the layer-aware `prune_dangling` and the
deterministic corridor order of the control generator. No manual track edits and no placement changes
were made (`verification/routing_iterations_power.md` 16.6; `routing_iterations_control.md` V2.1 sections).

## Known limitations

- The 8-direction search with bend penalties is opt-in: on the power board it took 1605 s (3.8 x the 417 s
  V2-geometry rebuild of the same session; the frozen V2 record is 523.657 s),
  left `LS_FB_VDD` and `VDD_L` unresolved and failed DRC 1 / 2 / 0 (manifest
  `verification/drc/20261012T084719Z-drc-93962d5d`, kept as history); on the control board 4205 s with one
  open connection (`ESTOP_N`) and 864 vias against 798 (power: `routing_iterations_power.md` 16.3; control:
  `verification/known_issues.md` V2.1-02, whose figures come from the orchestrator scratch record
  `scratchpad/v21/progress_router.md`, not in the repository; `routing_iterations_control.md` records 3.6 x run
  time with 1 unresolved).
- 1121 (power) and 1233 (control) 90-degree bends remain; most are legs too short for a fillet, frozen
  pad exits and corners with no clear chamfer; 141 / 341 are kept chains without an exception record.
- The smoothing is conservative by design: rewritten chains do not release their old occupancy, so later
  chains see stale halos and keep corners (`clearance` exceptions, 451 / 740 in the beautify reports).
- Zigzag runs rise (12 -> 26, 31 -> 41) because collapsed stairs leave chamfer pairs that the counter
  classifies as zigzags; the explanation is the implementers', not independently verified
  (`v21_validation.md` point 3).
- Four power and three control sheets are drawn on A2 with hull fills of 0.40-0.68; lane compaction
  is the next lever and was not done.
- Every local net keeps one global name tag so KiCad keeps the V2 net names; 40 / 18 of them are
  single labels that KiCad's default-ignored `single_global_label` check would warn about.
- One label fallback (`VIN_AMP_N`, power sheet 05) and one four-way junction on the power board.
- Readability is measured, not judged: crossings, overlaps and fills come from `schematic_metrics`
  with an estimated font metric; TIDA-010054 was the reference style, not a template.
- DNP footprints now carry the DNP attribute (power 16, control C54); `in_bom` / `on_board` unchanged.
- The control `.kicad_dru` carries PGND_LV conditions for a class the control project does not define
  (pre-existing, never matching); the suffix-less `stored_zone_fill_check.json` (a 2026-10-11 V2 diagnostic)
  still carries the V2 banner, while EX `manufacturing/README.md` was rewritten with the V2.1 banner after the
  validation run (`v21_validation.md` point 4 is stale); title fields read "AIPE V2 ..." by design.
- Regeneration reproduces copper and zones item for item, not file bytes (random KIIDs of tracks, vias
  and footprints); the inner-layer `source.occupancy` codes in the control routing records differ
  between builds.
- KR-ISO-002 B.Cu per-layer minimum 12.025 -> 11.932 mm (threshold 9.0 mm); the AMC1311 VOUT pair
  mismatch grew 1.758 -> 2.637 mm while both nets got shorter (`v21_validation.md` points 1, 2).
- The open V2 engineering issues keep their status: `verification/known_issues.md` (49 V2 rows, 15 of them
  annotated with the V2.1 value of a changed geometric number, plus the 18 new V2.1 rows V2.1-01..V2.1-18 that describe the points above), six power-board and two
  control-board metric rows above threshold, ten review findings NOT APPLIED. Zero native findings is a
  CAD statement, not electrical, thermal, EMI or insulation validation; nothing was built, energised or
  measured and no firmware exists.
